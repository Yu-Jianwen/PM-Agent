# hw-product-strategy — 产品规划与三定

## 1. Purpose（目的）

本 Skill 是 PM Agent 在产品规划阶段的核心技能。它解决"研究做完了，到底做什么产品、卖给谁、怎么卖、分几步走"的问题。

核心任务：
- 整合五份研究报告（市场 + 用户 + 竞品 + 合规 + 专利）的结论，形成综合判断
- 完成"三定"：定目标（目标市场/目标用户）、定定位（产品定位/差异化）、定路径（MVP/V1/V2 路线）
- 做出用户人群与场景的选择：哪些进入首版（MVP），哪些留到 V1/V2
- 做出竞品与差异化选择：对标谁、在哪打、怎么赢
- 识别关键风险、未验证假设及其验证路径
- 生成下游文档（MRD/BRD/产品定义/PRD/验证计划）的输入清单

在 PM Agent 工作流中，本 Skill 位于研究阶段（Phase 1）全部完成之后、规划阶段（Phase 2）的开端。它承接 Researcher 的五份报告和 evidence.csv，产出产品方向决策，为下游 hw-mrd-brd、hw-product-definition、hw-prd 提供方向性输入。

本 Skill 的每一条方向性结论（市场选择、用户选择、定位选择、路线选择）都必须标注 confidence（高/中/低）。低 confidence 的结论自动转化为待验证假设，写入验证路径。

## 2. Context（上下文/适用场景）

  - `09_竞品研究分析报告.md`（hw-competitive-analysis）
  - `17_产品合规研究报告.md`（hw-compliance-research，L2+ 路由）
  - `18_专利格局分析报告.md`（hw-patent-analysis，L3 路由）
- `registers/evidence.csv` 已有对应研究阶段的 evidence 记录
- `registers/assumptions.csv` 已有 Researcher 标记的未验证判断
- `registers/risks.csv` 已有 Researcher 识别的研究阶段风险

### 不负责

- 不执行新的市场/用户/竞品研究 — 那是 Researcher Agent 的工作。若发现研究缺口，记录为待补齐输入，不自行补研究。
- 不编写 MRD/BRD、产品定义或 PRD — 那是下游 PM Skill 的工作。本 Skill 只产出方向性输入清单。
- 不做技术可行性评估 — 那是开发团队的工作。技术约束作为输入条件使用，不自行判断。
- 不自行批准产品方向 — Gate 4 是人工决策点。decisions.csv 仅在 Gate 4 批准后写入。

## 3. Operating Principles（操作原则）

### 原则 1：三定是综合决策，不是研究转录

"三定"结论必须是对五份研究报告的**综合判断和取舍**，不能是各报告结论的机械汇总。市场研究说"市场大"、竞品研究说"竞品强"、用户研究说"用户需要 X"——这些是输入，不是决策。产品规划必须做出选择：市场大但选哪个细分？竞品强但我们在哪打？用户需要 X 但 MVP 做不做？

**反面行为**：将市场研究摘要、用户研究摘要、竞品研究摘要分别粘贴到报告第 3 节"研究结论综合"，然后第 4 节"三定结论"直接复制第 3 节的内容，没有做出任何取舍决策。

**违反后果**：产品规划报告沦为"研究报告汇编"，没有提供任何方向性决策。Reviewer 标记 severity=blocker，Gate 4 退回。下游 Skill（MRD/BRD、产品定义）无法获得明确的产品方向输入。

---

### 原则 2：每个方向性结论必须标注 confidence

目标市场选择、用户人群选择、定位决策、差异化方向、MVP 范围——每一条方向性结论必须标注 confidence（高/中/低）。confidence=低 的结论自动转化为待验证假设（写入 assumptions.csv 或在报告中标记验证路径），不能当作既定事实传递给下游。

**反面行为**：所有结论统一不标 confidence，或全部标"高"以显示"研究充分"。或低 confidence 的结论直接写入 decisions.csv 而不附带验证计划。

**违反后果**：下游 Skill 基于低 confidence 的方向性决策展开 MRD/PRD，后期假设被推翻时返工成本指数级上升。Reviewer 在 Gate 4 检查 confidence 标注完整性，缺失者退回。

---

### 原则 3：用户与场景选择必须显式排除

报告第 5 节"用户与场景选择"必须明确列出哪些人群/场景**进入 MVP**、哪些**进入 V1/V2**、哪些**明确放弃**。不能只列"目标用户"而不说明"被排除的用户是谁、为什么排除"。

**反面行为**：目标用户写成"25-45 岁城市中产"，但没有说明为什么排除了 18-24 岁、46+ 岁、农村用户。或 MVP 场景写成"核心使用场景"，但没有说明为什么某几个高频场景被留到 V1。

**违反后果**：产品边界模糊，PRD 阶段开发团队会问"这个人群要不要覆盖？" → 没有答案 → 范围蔓延。Reviewer 检查排除理由是否充分，无理由的排除视为遗漏。

---

### 原则 4：decisions.csv 仅在 Gate 4 人工批准后写入

产品方向性决策（目标市场选择、产品定位、MVP 范围、路线图）必须经过 Gate 4 人工审批确认后，才写入 decisions.csv。Agent 不自行批准产品方向。

**反面行为**：在产品规划报告写完后，立即在 decisions.csv 中追加"DEC-{project}-004: 目标市场选定为北美"等决策记录，不等 Gate 4 审批。或在 Gate 4 摘要中标注"以上决策已自动生效"。

**违反后果**：decisions.csv 中出现未经人工确认的方向性决策记录，台账可信度归零。下游 Skill 基于错误的"已批准"状态开始执行，整个项目的审计链断裂。对齐 AGENTS.md 台账规则：decisions 写入时机为"人工确认后写入"。

---

### 原则 5：路线图必须在 MVP 边界清晰后才定义

V1/V2 路线图的内容（增强功能、新增人群、扩展市场）必须基于 MVP 的选择结果推导。不能在 MVP 范围未锁定时就定义 V1/V2——否则 V1/V2 可能是对"理想产品"的想象而非对"MVP 之后的增量"的规划。

**反面行为**：先列一个"终极产品愿景"的功能清单，然后随意切分成 MVP/V1/V2 三块。或 V1 的内容和 MVP 无逻辑递进关系（如 MVP 是硬件基础版，V1 突然跳到 AI 全功能版）。

**违反后果**：路线图不可执行——V1 的输入条件（MVP 的用户反馈、供应链磨合、认证完成）与 V1 的内容不匹配。开发团队无法按路线图规划资源和排期。

---

### 原则 6：竞品差异化必须是对比后的选择，不是愿望清单

差异化方向必须基于竞品研究报告中**可验证的竞品弱项或空白**，不能是"我们要做得更好"的愿望清单。每条差异化声明必须引用 evidence.csv 中的竞品证据或用户痛点证据。

**反面行为**：差异化写成"我们的产品更智能、更好看、更便宜"——三个维度同时差异化等于没有差异化。或差异化方向没有竞品证据支撑，仅来自 PM 的直觉。

**违反后果**：差异化不可信——Reviewer 要求每条差异化提供 evidence 关联，无法提供者标记 severity=blocker。下游产品定义和 PRD 基于虚假差异化展开，产品上市后发现和竞品拉不开差距。

## 4. Instructions（分步骤指引）

### Step 1：加载全部已批准研究报告

- **输入**：
  - `output/{project}/01_产品市场与机会研究报告.md` — 市场研究报告
  - `output/{project}/10_用户研究与VOC分析报告.md` — 用户研究报告
  - `output/{project}/09_竞品研究分析报告.md` — 竞品研究报告
  - `output/{project}/17_产品合规研究报告.md` — 合规研究报告（L2+ 路由）
  - `output/{project}/18_专利格局分析报告.md` — 专利分析报告（L3 路由）
  - `registers/evidence.csv` — 研究阶段全部 evidence 记录
  - `registers/assumptions.csv` — 研究阶段全部 assumption 记录
  - `registers/risks.csv` — 研究阶段全部 risk 记录
  - `registers/decisions.csv` — 确认 Gate 2 和 Gate 3 审批状态

- **操作**：
  1. 确认 Gate 2 和 Gate 3 的 decisions.csv 记录存在且 status=approved
  2. 读取每份研究报告的**摘要章节**（≤500 字的核心发现），提取关键结论
  3. 读取每份研究报告的**输入来源表**，确认各自使用的证据范围
  4. 从 evidence.csv 中提取研究阶段的所有记录（按 project 过滤），建立 evidence 索引
  5. 从 assumptions.csv 中提取所有未验证假设（status=open），标注哪些 confidence=高 但 validation_method 为空
  6. 从 risks.csv 中提取所有风险记录，标注哪些 impact=高 或 probability=高
  7. 对于 L1/L2 路由被裁剪的研究报告（合规、专利），在输入来源表中标记为"裁剪 — 替代证据：{来源}"而非"缺失"

- **检查点**：
  - [ ] Gate 2 和 Gate 3 审批记录已验证（decisions.csv 中存在 approved 记录）
  - [ ] 所有研究报告的摘要已提取（≥1 条关键结论 per 报告）
  - [ ] evidence 索引已建立（至少包含研究阶段的 evidence_id 列表）
  - [ ] 未验证高置信度假定已标记（如有）
  - [ ] 高影响/高概率风险已标记（如有）
  - [ ] 被裁剪报告的替代证据已记录

---

### Step 2：验证输入完整性

- **输入**：Step 1 的研究报告摘要 + evidence 索引 + 路由等级（L1/L2/L3）

- **操作**：
  1. 按"输入来源与完整性"表（报告模板第 2 节）逐项检查：
     - 市场机会 → 来源：市场研究报告 + evidence.csv 中市场相关记录
     - 用户人群与场景 → 来源：用户研究报告 + evidence.csv 中用户相关记录
     - 竞品与替代方案 → 来源：竞品研究报告 + evidence.csv 中竞品相关记录
     - 商业可行性 → 来源：BRD/商业测算（如已有），否则标记为"阶段性"
     - 内部能力与约束 → 来源：技术/供应链/渠道/服务输入（如已有），否则标记为"待补齐"
     - 关键风险 → 来源：risks.csv
  2. 对每条输入项，标注状态：
     - **已验证**（verified）：有 A/B 级 evidence + 研究报告已通过 Reviewer 审查
     - **阶段性**（partial）：有 C 级 evidence 或仅有部分覆盖；需在 Gate 4 前明确的缺口
     - **缺失**（missing）：无 evidence 记录；阻塞产品规划的关键维度（阻塞=是）
  3. 对"阶段性"和"缺失"的输入项，评定对规划的影响（高/中/低）和缺口处理方式：
     - 影响=高 且 缺失 → 阻塞：不能继续产品规划，必须先补齐
     - 影响=中 且 阶段性 → 不阻塞但有风险：记录为待补齐项，标注截止 Gate
     - 影响=低 且 缺失 → 非阻塞：记录原因，下游 Skill 自行处理

- **检查点**：
  - [ ] 6 个输入项全部有状态标记（已验证/阶段性/缺失），无空白行
  - [ ] 所有"缺失 + 影响=高"的条目有明确的阻塞说明和处理方案
  - [ ] 所有"阶段性"条目有明确的缺口描述和补齐截止 Gate
  - [ ] 无"缺失 + 影响=高 + 无处理方案"的条目（存在则阻塞后续步骤）

---

### Step 3：综合研究发现

- **输入**：Step 1 的研究报告摘要 + Step 2 的输入完整性评估

- **操作**：
  1. 按五个维度（市场/用户/竞品/商业/自身能力）提炼关键结论：
     - **市场维度**：市场规模（TAM/SAM/SOM）、增长率、市场阶段（导入/成长/成熟/衰退）、关键驱动因素、进入壁垒
     - **用户维度**：核心用户人群、关键 JTBD、未被满足的需求、支付意愿、购买决策链
     - **竞品/替代方案维度**：核心竞品定位、竞品弱项/空白、替代方案威胁程度
     - **商业维度**：价格带、成本结构、渠道模式、收入模型、盈亏平衡预估
     - **自身能力维度**：技术储备、供应链能力、渠道覆盖、品牌积累、团队能力
  2. 识别**跨维度的矛盾或张力**：
     - 例：市场研究显示"高端市场增长快" vs 用户研究显示"用户价格敏感度高"
     - 例：竞品研究显示"竞品技术壁垒高" vs 自身能力评估显示"技术储备不足"
     - 这些矛盾必须在"三定"结论中做出取舍，不能两条路都走
  3. 识别**关键不确定性**：哪些结论只有一个来源支撑？哪些结论来自 C/D 级源？哪些维度完全没有数据？
  4. 将综合结论填入报告第 3 节"研究结论综合"表格，每条结论标注 evidence 来源和对规划的影响方向

- **检查点**：
  - [ ] 五个维度（市场/用户/竞品/商业/自身能力）全部有结论，无空白维度
  - [ ] 每条结论标注了 evidence 来源（evidence_id 或报告章节引用）
  - [ ] 跨维度矛盾已显式识别（≥0 条，如有则已标注）
  - [ ] 关键不确定性已列出（≥0 条，如有则标注了 confidence 和下一步处理）

---

### Step 4：形成"三定"结论

- **输入**：Step 3 的综合研究结论 + 跨维度矛盾 + 关键不确定性

- **操作**：

  这是本 Skill 最核心的步骤。"三定"是对以下十个方向的**综合决策**——不是对研究结论的逐条回应，而是在矛盾中做选择、在不确定性中做判断。

  对每个方向，按以下逻辑做出决策并填写：

  1. **定目标市场**：从市场研究识别的多个候选市场中，选择 1 个主要目标市场。说明选择理由（市场规模/增长/进入壁垒/自身能力匹配）和排除其他市场的理由。

  2. **定目标用户**：从用户研究识别的多个人群中，选择 1-2 个核心用户人群。说明选择理由（需求强度/支付意愿/触达可行性）和排除其他人群的"为什么不是现在"。

  3. **定客户/决策角色链**：确定使用者、决策者、付费者、安装/维护者分别是谁。B2B 场景需明确决策链；B2C 场景明确购买决策影响因素。

  4. **定核心场景**：从用户研究的 JTBD 中，选择进入 MVP 的 1-3 个核心场景。每个场景标注：为什么这个场景优先？被排除的高频场景是哪些、为什么留到 V1/V2？

  5. **定产品定位**：一句话定位陈述——"为{目标用户}提供{核心价值}的{产品品类}，不同于{参照竞品}，我们{差异化}。"定位陈述必须能回答"如果用户问'你和 XX 有什么不同'，怎么回答？"

  6. **定参照品类/替代方案**：明确用户在做购买决策时会拿什么跟我们的产品比。不只是同类竞品，也包括非同类替代方案（如智能锁 vs 传统锁 vs 不装锁）。

  7. **定差异化**：从竞品研究中识别可验证的竞品弱项或空白，选择 1-2 个主差异化方向。每个差异化方向必须：(a) 用户在乎（有用户研究证据）；(b) 竞品没做好（有竞品研究证据）；(c) 我们能做好（有能力证据或假设）。

  8. **定价格带/成本目标**：基于市场研究的价格带分布、竞品定价、用户支付意愿，确定目标价格带和 BOM 成本目标。

  9. **定 MVP**：基于以上所有决策，定义 MVP 的精确范围——包括什么（核心功能/核心人群/核心场景/核心市场）和不包括什么（明确排除，标注去向：V1/V2/放弃）。

  10. **定 V1/V2 路线**：定义 V1（量产首版）和 V2（增强版）的增量内容、目标、前提条件和触发条件。

  **每条"定"的结论必须标注 confidence（高/中/低）**：
  - 高：有 ≥2 条 A/B 级 evidence 支撑，研究结论一致，无跨维度矛盾
  - 中：有 ≥1 条 A/B 级 evidence 支撑，或存在 1 个跨维度矛盾已做出明确取舍
  - 低：仅有 C 级 evidence 或无 evidence 支撑，基于推断或假设

- **检查点**：
  - [ ] 10 个"定"全部有内容，无空白项
  - [ ] 每条结论标注了 confidence（高/中/低）
  - [ ] 目标市场/目标用户/差异化选择有"排除理由"（为什么不是其他选项）
  - [ ] 产品定位陈述是一句话，可直接用于对外沟通
  - [ ] 差异化方向引用 ≥1 条 evidence（evidence_id 或报告章节）
  - [ ] 所有 confidence=低 的结论在风险/假设表中作为待验证项出现

### Step 5：选择用户人群与场景进入 MVP

- **输入**：Step 4 的三定结论（目标用户 + 核心场景 + MVP 范围）+ 用户研究报告

- **操作**：
  1. 将用户研究报告中的所有候选人群/角色列在"用户与场景选择"表（报告模板第 5 节）中：
     - 候选人群 A、B、C...
     - 使用者、决策者、付费者、安装/维护者
  2. 对每个人群/角色，填入：
     - **是否进入首版**（MVP）：是/否
     - **选择依据**：为什么进入/不进入？引用 evidence 支撑
     - **不选择原因**：如果不进入，为什么？不能只写"优先级低"——必须写具体原因（如"需求强度不足""触达成本过高""群体规模太小""与 MVP 定位冲突"）
     - **后续处理**：V1 / V2 / 放弃 / 继续验证
  3. 对"是"的人群/角色，确认 MVP 范围内为他们解决的核心场景已覆盖
  4. 对"继续验证"的人群/角色，在报告第 8 节"风险、假设与验证路径"中登记验证方案
  5. 特别关注**决策者和付费者不是使用者**的场景（如 B2B、儿童产品、老人产品）：如果决策者和付费者不在 MVP 覆盖范围，MVP 的产品定义是否需要满足他们的诉求？

- **检查点**：
  - [ ] 所有候选人群/角色已列出（从用户研究报告提取，不遗漏）
  - [ ] 每个候选人群/角色的"是否进入首版"已明确
  - [ ] 每个"否"的人群/角色有具体的"不选择原因"和"后续处理"
  - [ ] MVP 范围内的人群/角色，其核心场景已在三定中覆盖
  - [ ] 决策者/付费者/使用者分离的场景已显式处理

### Step 6：选择竞品对标与差异化方向

- **输入**：Step 4 的三定结论（差异化 + 参照品类）+ 竞品研究报告 + evidence.csv 中竞品相关 evidence

- **操作**：
  1. 从竞品研究报告中提取所有竞品和替代方案，列在"竞品与差异化选择"表（报告模板第 6 节）中
  2. 对每个竞品/替代方案，标注：
     - **类型**：直接竞品 / 标杆 / 价格杀手 / 非同类替代 / 潜在进入者
     - **关键结论**：这个竞品对我们的产品规划最重要的一条结论（≤2 句话，引用 evidence）
     - **对我方规划的影响**：定位影响 / 成本影响 / 结构影响 / 体验影响
     - **进入下游**：此竞品信息需要进入哪些下游文档（产品定义 / PRD / 验证）
  3. 选择**主对标竞品**（1 个）：用户最可能拿我们跟它比的那个竞品。差异化方向围绕与此竞品的对比展开。
  4. 选择**次要参照**（1-2 个）：在特定维度上值得学习或警惕的竞品/替代方案。
  5. 验证差异化方向的可信度：
     - 这个差异化用户在乎吗？→ 引用用户研究 evidence
     - 竞品在这个维度上确实弱/空白吗？→ 引用竞品研究 evidence
     - 我们有能力在这个维度上做好吗？→ 引用内部能力证据或标记为假设

- **检查点**：
  - [ ] 所有竞品/替代方案已列出（从竞品研究报告提取，不遗漏）
  - [ ] 主对标竞品已选定并注明选择理由
  - [ ] 每条差异化方向有 ≥2 条 evidence 支撑（用户在乎 + 竞品弱/空白）
  - [ ] 差异化方向的可实现性已评估（能力证据或假设标记）
  - [ ] 竞品信息进入下游文档的映射已标注

### Step 7：定义 MVP/V1/V2 路线图

- **输入**：Step 4 的三定结论（MVP + 路线）+ Step 5 的用户选择 + Step 6 的竞品选择

- **操作**：
  1. 定义每个阶段的完整画像（报告模板第 7 节"路线图与阶段目标"表）：

     **MVP/概念样机阶段**：
     - 目标：验证什么？（核心假设 / 技术可行性 / 用户价值 / 商业可行性）
     - 核心能力：必须具备的最小能力集（功能/性能/体验）
     - 关键约束：受什么限制？（预算/时间/技术/供应链/认证）
     - 验证重点：MVP 阶段结束后，什么指标决定"通过/不通过/转向"？
     - 明确列出 MVP **不包含**的内容及其去向（V1 / V2 / 放弃）

     **V1/量产首版阶段**：
     - 目标：从概念验证到可量产、可销售的完整产品
     - 核心能力：在 MVP 基础上增加的增量能力
     - 关键约束：量产约束（良率/产能/成本/BOM 锁定）、认证完成、渠道就绪
     - 验证重点：量产一致性、用户满意度、渠道接受度
     - V1 的**前提条件**：MVP 验证通过的具体标准

     **V2/增强版阶段**：
     - 目标：基于 V1 市场反馈的产品增强或市场扩展
     - 核心能力：V1 基础上增加的增量能力（新增人群/新场景/新市场/新功能）
     - 关键约束：V1 的反馈数据就绪、供应链和产能可以支撑增量
     - 验证重点：新增能力是否带来增量用户/增量收入
     - V2 的**触发条件**：什么数据和反馈触发 V2 启动？（如"NPS ≥40""月活 ≥X""退货率 <Y%"）

  2. 检查 MVP→V1→V2 的**逻辑递进性**：
     - V1 的内容是否直接响应 MVP 的验证结果？
     - V2 的内容是否基于 V1 的市场反馈假设？
     - 每个阶段的目标是否可验证（有明确的 go/no-go 标准）？

  3. 绘制路线图的时间线（不要求精确日期，但要标注阶段间的依赖关系）：
     ```
     MVP (概念样机) ──[验证通过]──> V1 (量产首版) ──[市场反馈]──> V2 (增强版)
          │                              │
          └── [验证失败] ──> 转向/终止     └── [反馈负面] ──> 修正路线
     ```

- **检查点**：
  - [ ] 三个阶段（MVP/V1/V2）全部有定义，无空白阶段
  - [ ] 每个阶段有明确的目标、核心能力、关键约束、验证重点
  - [ ] MVP 的"不包含"内容已显式列出及其去向
  - [ ] V1 的前提条件已定义（MVP 验证通过的具体标准）
  - [ ] V2 的触发条件已定义（什么数据/反馈触发 V2 启动）
  - [ ] MVP→V1→V2 存在逻辑递进关系，不是功能的随意切分

### Step 8：识别关键风险、假设与验证路径

- **输入**：Step 4-7 的所有方向性决策 + risks.csv + assumptions.csv + 所有 confidence=低 的三定结论

- **操作**：
  1. 汇总所有需要验证的项（报告模板第 8 节"风险、假设与验证路径"表）：

     **假设类**（来自 assumptions.csv 或三定中 confidence=低的结论）：
     - 逐条列出每条假设的当前状态（待验证/已验证/已证伪）、验证方式和去向
     - 高 impact + 未验证的假设 → 优先放入验证计划（hw-validation-plan 输入）
     - confidence=低 的三定结论自动转化为假设

     **风险类**（来自 risks.csv 或本 Skill 新识别的风险）：
     - 逐条列出风险内容、影响（高/中/低）、验证方式和去向
     - 重点关注"三定选择"带来的新风险：
       - 例：选择了小众细分市场 → 市场规模可能不足以支撑商业目标
       - 例：差异化方向依赖新技术 → 技术可行性未验证
       - 例：MVP 排除了某核心场景 → 早期用户可能认为产品不完整

  2. 对每条假设和风险，指定**验证方式**：
     - 用户验证（user trial / concept test / pricing test）
     - 技术验证（prototype / bench test / feasibility study）
     - 市场验证（pilot launch / channel test / pre-sale）
     - 供应链验证（supplier audit / sample run / cost quotation）
     - 认证验证（pre-compliance test / certification body consultation）

  3. 标记每条假设/风险的**去向**（哪个下游文档/台账需要此项）：
     - assumptions.csv（更新 validation_method 字段）
     - risks.csv（追加新风险记录）
     - 验证计划（hw-validation-plan 的核心输入）

- **检查点**：
  - [ ] 所有 confidence=低 的三定结论已转化为假设 + 验证路径
  - [ ] 所有高 impact 假设有明确的验证方式
  - [ ] 所有高 impact 风险有明确的缓解措施或验证方案
  - [ ] 新识别的风险已准备追加到 risks.csv（在 Gate 4 批准后写入）
  - [ ] 每条假设/风险标注了去向（assumptions.csv / risks.csv / 验证计划）

追加时不覆盖已有记录。seq 接续 decisions.csv 中已有最大序号 +1。

## 6. Quality Bar（最低质量标准）

Reviewer 将按以下 checklist 逐项检查。全部通过方可进入 Gate 4 审批流程。

- [ ] **一页结论完整**：第 1 节所有 12 个字段（规划结论/目标市场/目标用户/核心客户/产品定位/差异化/价格带/MVP/V1V2/最大风险/进入条件/整体置信度）已填写，无空白
- [ ] **三定结论 10 个"定"全覆盖**：第 4 节 10 个决策维度全部有结论 + confidence + 依据 + 排除选项（适用时），无"待定"或空白
- [ ] **每条结论有 confidence**：三定结论（第 4 节）、研究综合（第 3 节）、一页结论（第 1 节）中所有方向性声明标注了 confidence（高/中/低）
- [ ] **排除理由具体**：第 5 节用户选择中每个"否"的人群/角色有具体的"不选择原因"（不能是"优先级低"或"后续考虑"等模糊表述）；第 4 节三定结论中"排除的选项及理由"列非空
- [ ] **差异化有 evidence**：第 6 节差异化方向验证表中，每个差异化方向至少引用了"用户在乎"和"竞品弱/空白"两个维度的 evidence（evidence_id 或报告章节）
- [ ] **路线图递进逻辑成立**：MVP → V1 → V2 的阶段内容存在递进关系——V1 增量直接响应 MVP 验证目标，V2 增量基于 V1 市场反馈假设；每个阶段有明确的 go/no-go 标准
- [ ] **confidence=低 有验证路径**：第 4 节所有 confidence=低 的三定结论在第 8 节中有对应的假设 + 验证方式记录（覆盖率 100%）
- [ ] **下游输入清单完整**：第 9 节覆盖了全部 5 个下游文档（MRD/BRD/产品定义/PRD/验证计划），每个标注了输入内容和状态
- [ ] **输入来源表完整**：第 2 节 6 个输入项全部有状态标记（已验证/阶段性/缺失）；所有"缺失 + 影响=高"的条目有明确处理方案
- [ ] **无占位符**：全文不包含 TBD、TODO、"根据实际情况调整"、"待定"等占位符文本
- [ ] **decisions.csv 未被提前写入**：在产品规划报告产出时，decisions.csv 中不存在对应此项目的 product_direction 类记录（可在 Gate 4 批准前通过检查 decisions.csv 的最后修改时间和内容来验证）
- [ ] **ID 格式合规**：所有 evidence_id 引用符合 EV-{project}-{seq}，所有 risk_id 符合 RISK-{project}-{seq}，所有 assumption_id 符合 A-{project}-{seq}

## 8. Best Practices（最佳实践）

### 好的输出 vs 差的输出

**好的三定结论（定产品定位）：**

```
定产品定位：
结论：为北美租住公寓的年轻白领（25-35岁）提供无需布线、App自由控制的智能安防套件。
不同于 Ring Alarm，我们无需专业安装、无需月费订阅、支持租房场景的免损拆装。
Confidence：中
依据：EV-CWLS-003（用户研究：78%租房者拒绝打孔安装），EV-CWLS-007（竞品研究：Ring 月费$20是用户流失首因），EV-CWLS-012（市场研究：DIY安防市场CAGR 22%）
排除的选项及理由：排除"全屋智能安防系统"定位——面向 homeowner，需要专业安装和月费订阅，与核心用户"租房白领"不匹配；排除"超低价安防摄像头"定位——价格杀手竞品（Wyze）已占据此定位，且毛利率不足以支撑渠道
```

**差的三定结论：**

```
定产品定位：
结论：做一款好用的智能安防产品
Confidence：—
依据：市场研究显示智能安防有需求
排除的选项及理由：—
```
问题：定位不可沟通（"好用"无法区别于竞品）、无 confidence、无 evidence 引用、无排除分析、无法回答"你和 Ring 有什么不同"。

---

**好的用户选择（排除理由）：**

```
| 候选人群 B：55+ 岁退休居家老人 | 否 | — | 此人群对手机 App 操作的学习成本高（EV-CWLS-015），优先触达成本低、使用意愿强的年轻用户。老人群体留到 V2 通过"子女远程管理"模式覆盖，降低老人的直接操作门槛。 | V2 |
```

**差的用户选择：**

```
| 候选人群 B：老人 | 否 | — | 优先级低 | 后续考虑 |
```
问题：排除理由模糊（"优先级低"不解释为什么优先级低），"后续考虑"太含糊。

---

**好的差异化方向验证：**

```
| 差异化方向 | 用户在乎吗？ | 竞品弱/空白？ | 我们能做好吗？ | 整体可信度 |
|-----------|------------|-------------|-------------|-----------|
| 3M胶贴安装，无需打孔 | 是：78%租房者拒绝打孔安装（EV-CWLS-003） | 是：Ring/SimpliSafe均需螺丝固定（EV-CWLS-007） | 假设：3M VHB胶带在墙纸表面的长期可靠性待验证（A-CWLS-005） | 中 |
```

**差的差异化方向验证：**

```
| 差异化方向 | 用户在乎吗？ | 竞品弱/空白？ | 我们能做好吗？ | 整体可信度 |
|-----------|------------|-------------|-------------|-----------|
| 更好的用户体验 | 是 | 是 | 是 | 高 |
```
问题：三个维度全是"是"但无证据，"更好的用户体验"不可验证——什么是"更好"？

---

**好的路线图 go/no-go 标准：**

```
MVP → V1 前提条件：
1. 概念样机通过 100 人用户试用，任务完成率 ≥80%，NPS ≥30
2. 3M 胶贴安装方案通过 30 天长期可靠性测试（温度 -10°C~50°C，湿度 20%~90%），脱落率 = 0%
3. BOM 成本确认 ≤$25（含传感器+主控+结构件），满足 $49.99 零售价目标
4. 至少 1 家北美连锁零售渠道确认产品概念兴趣（LoI 或口头确认）
```

**差的路线图 go/no-go 标准：**

```
MVP → V1 前提条件：MVP 验证通过
```
问题：无量化标准，无法判断"通过"和"不通过"的边界。

### 常见陷阱

| 陷阱 | 表现 | 正确做法 |
|------|------|----------|
| 研究转录而非综合决策 | 三定结论 = 研究报告摘要的重新排列，没有取舍 | 每个"定"写完后反问：如果只让选一个，选哪个？被排除的那个，为什么排除？ |
| "既要又要"式三定 | 目标用户写 5 个人群、差异化写 3 个方向、MVP 包含"能做多少做多少" | 目标用户 ≤2 个核心人群；差异化 1-2 个主方向；MVP 明确定义"不做什么" |
| confidence 全部标"高" | 不论证据是否充分，所有结论统一标"高"以显示"研究扎实" | 诚实标注。confidence=低 不可耻——它意味着你识别了不确定性并规划了验证路径 |
| 差异化没有竞品证据 | 差异化方向来自 PM 直觉（"我觉得用户会喜欢更好的续航"），而非竞品研究报告 | 每条差异化引用 2 条 evidence：用户在乎（用户研究）+ 竞品没做好（竞品研究） |
| 路线图是功能清单的切分 | MVP/V1/V2 内容是产品终极形态的功能列表三等分，各阶段之间无逻辑递进 | MVP→V1 是"验证→量产"的递进；V1→V2 是"反馈→增强"的递进。每个阶段的目标、约束、验证重点不同 |
| 排除说明缺失或模糊 | 只写"目标用户是 X"，不写"为什么不是 Y"；或者写"Y 优先级低"但不解释为什么低 | 每个排除项写具体原因：需求强度/触达成本/市场规模/与定位冲突/技术限制/阶段策略 |
| 忽略"不通过"的决策路径 | 路线图只写怎么往下走，不写什么条件下转向或终止 | 每个阶段转换明确 go/no-go 标准 + 转向/终止条件。不是所有产品都应该一直做下去 |
| Gate 4 前写入 decisions.csv | 产品规划报告写完就追加 decision 记录，或把"建议"写成"已决策" | decisions.csv 中的 product_direction 记录必须在 Gate 4 人工批准后才出现。可通过对比 decided_at 和 Gate 4 批准时间戳验证 |
