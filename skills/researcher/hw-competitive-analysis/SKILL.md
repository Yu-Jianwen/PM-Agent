# 硬件竞品研究分析（hw-competitive-analysis）

## 1. Purpose（目的）

本 Skill 解决"竞品为什么赢、哪里弱、成本和结构怎么做"的问题。它是 Researcher Agent 竞品分析能力的执行体，承接 hw-market-study 产出的核心竞品清单，通过桌面数据采集、拆机/BOM 反推、供应链追溯和交叉对比，输出可被产品规划和产品定义直接消费的竞品洞察。

在 Agent 工作流中的位置：

```
hw-market-study → hw-competitive-analysis → hw-product-strategy
     (并行: hw-user-research)
```

本 Skill 的产出直接回答 PM 在产品规划阶段必须确认的问题：竞品的功能边界、成本结构、供应链依赖、用户口碑弱点和差异化机会。

### 触发条件

- Gate 1 已批准（路由判定完成）

- PM 确认需要深度竞品分析（非仅桌面扫描）

## 3. Operating Principles（操作原则）

### P1: BOM 成本是估算，除非供应商报价确认

**原则**：BOM 成本反推本质上是基于公开器件价格（LCSC、1688、digikey）和拆机识别的估算。只有供应商正式报价单（RFQ 回复）才可以标记为"已确认成本"。

**反面行为**：将 LCSC 批量单价直接当作竞品采购价；用零售价推断采购成本而不标记置信度折扣。

**违反后果**：成本目标偏差传导到 BRD 定价模型，导致商业可行性误判。Reviewer 发现后标记为 blocker finding（severity: high）。

### P2: 单机拆解数据不等于代表性样本

**原则**：一台竞品的拆解数据反映的是该特定批次、该特定设备的制造状态。竞品可能在不同批次中更换了器件（特别是存储、电源芯片、传感器），也可能存在区域特供版本。

**反面行为**：基于一台设备的拆解声称"竞品使用的是 X 芯片方案"而不附加版本/批次说明；将单一拆解数据推广为"该品类的主流方案"。

**违反后果**：误导硬件选型决策。如果竞品实际已迭代到新方案而我方基于旧拆解数据对标，将导致产品上市即落后。Reviewer 对此类声明执行 Lens 1（源忠实度）核验。

### P3: 每条发现必须有 source_grade 和 direct_quote

**原则**：竞品分析报告中的所有核心发现（特别是用于支撑差异化决策的发现）必须携带 source_grade（A/B/C/D）和源文 direct_quote。桌面数据的 direct_quote 是截取/引述的原文；拆机数据的 direct_quote 是具体的器件丝印/PCB 编号/结构特征描述。

**反面行为**：写"竞品 A 用户普遍反馈连接不稳定"而不列出具体的用户评论原文和评论数量；声称"竞品 B 的 BOM 成本约 X 元"而不展示每个器件的估算来源。

**违反后果**：无法溯源的研究发现将被 Reviewer 在执行 3-Lens 对抗性验证时标记为 `evidence` 类别 finding（severity: blocker）。证据不可溯源 = 结论不可采信。

### P4: 桌面数据不等于产品真实体验

**原则**：电商 listing 参数、品牌官网宣传、测评视频结论均代表竞品"声称的"或"被展示的"表现，不等于产品在真实用户环境中的实际体验。应明确区分"品牌声称"和"第三方验证/用户反馈证实"。

**反面行为**：将电商详情页的参数直接写入对标矩阵而不标记来源为"品牌自述"；用品牌宣传视频中的安装耗时当作真实安装耗时。

**违反后果**：对标基准失真。用户实际体验与桌面研究结论之间的差距 → 产品定义阶段的功能取舍依据不牢。

### P5: 不确定默认降级，不默认乐观

**原则**：当器件来源无法从拆机确认（如芯片被打磨、定制 ASIC、封胶遮挡），标记为"未识别"，将 BOM 估算置信度降为"低"。当供应链信息仅来自单一来源（如一篇行业文章），标记为"单源待验证"。

**反面行为**：对无法识别丝印的芯片猜测型号；对不确定的供应商关系写"据推测"而不标记置信度。

**违反后果**：不确定性在报告中逐层放大。产品规划阶段基于"中置信度假装高置信度"的数据做出的三定决策，将在 PRD 阶段被 Reviewer 用 Lens 2（矛盾搜索）发现矛盾。按 market-deep-research 投票规则：≥2 refutes → KILL 该结论。

## 4. Instructions（分步骤指引）

Think Step by Step。每一步包含输入、操作、检查点。

---

### Step 1: 加载竞品清单与上下文

**输入**：
- 读取 `output/{project}/market_study_report.md` 中 "4.3 看竞争" 章节
- 提取：核心竞品清单（含类型、选择理由）、替代方案清单、待专项研究问题
- 读取 `output/{project}/project_profile.json`（如有），提取目标市场、价格带、产品品类

**操作**：
1. 将竞品清单整理为研究计划表，逐竞品分配研究深度（桌面/购买/安装/拆机/BOM/售后）
2. 对每个竞品标注已有的数据来源路径（来自 market study 中已采集的电商/社媒线索）
3. 识别研究缺口：哪些竞品缺拆机数据、哪些缺评论分析、哪些缺价格历史

**检查点**：
- [ ] 竞品清单中每个对象的"研究深度"已明确标注
- [ ] 待专项研究问题已映射到具体竞品（每个问题 ≥1 个竞品对应）
- [ ] 研究缺口已在研究范围中显式声明（"本报告不覆盖 X 竞品的拆机分析，因该竞品尚未购买"）

---

### Step 2: 逐竞品桌面数据采集

**输入**：Step 1 的竞品清单和研究计划

**操作**：
对于每个竞品，按以下维度执行桌面数据采集：

| 维度 | 采集方法 | 工具 |
|------|---------|------|
| 销售表现 | 搜索电商平台（京东/天猫/亚马逊）的销量排名、评价数、价格历史 | WebSearch, WebFetch |
| 参数规格 | 采集官网产品页、电商详情页的核心参数表（尺寸/重量/功耗/通信协议/认证） | WebFetch |
| 宣传卖点 | 提取品牌详情页的主标题、核心卖点文案、视频话术 | WebFetch |
| 用户口碑 | 搜索用户评论（好评高频词、差评高频词、退货原因） | agent-reach（小红书/B站/抖音/知乎）+ WebSearch |
| 社媒讨论 | 搜索测评视频、开箱帖、对比帖中的关键结论 | agent-reach（B站/YouTube/小红书） |
| 认证信息 | 查询产品认证公告（CCC/FCC/CE 等） | WebSearch（std.samr.gov.cn, fccid.io） |

每条采集到的数据点立即写入 evidence.csv，格式为：`EV-{project}-{seq}`。

**检查点**：
- [ ] 每个竞品至少覆盖 5/8 桌面研究维度（销售表现、参数规格、宣传卖点、用户好评、用户差评、售后反馈、社媒讨论、认证信息）
- [ ] 每条桌面数据 evidence 记录包含 direct_quote（用户原话/官网原文/参数截图描述）
- [ ] source_grade 已标记（官方产品页 = B，电商 listing = C，社媒个人帖 = D）

---

### Step 3: 逐竞品拆机/BOM 分析

**输入**：Step 2 的桌面数据 + 可获取的拆机数据源

**操作**：
1. **搜索已有拆解报告**：在 iFixit、B站、YouTube、专业拆解网站搜索竞品拆解视频/图文
2. **执行拆解分析**（如已购买竞品）：按以下维度记录：
   - 拆解难度（螺丝数量、卡扣数量、胶粘固定点、需要特殊工具的位置）
   - 结构件数量和固定方式（螺丝/卡扣/胶/焊接/超声波焊接）
   - PCB 层数和 layout 复杂度
   - 关键器件识别（主控芯片型号+丝印、通信模组、传感器型号、电源芯片、执行器/电机）
   - 走线与连接器类型和数量
   - 密封/防护设计（密封圈、灌封胶、防水透气膜）
   - 散热方案（散热片、导热垫、风道设计）
3. **BOM 成本反推**：
   - 对可识别型号的器件，在 LCSC/digikey/1688 查询批量价格
   - 对定制件（外壳、专用结构件），按材料+工艺估算（注塑件按重量+模具分摊，CNC件按加工工时）
   - 汇总 BOM 表格（模块 → 器件 → 型号 → 数量 → 估算单价 → 估算小计）
4. 每条拆机发现写入 evidence.csv，source_grade 规则：
   - 自有拆解 + 器件丝印可读 = B+
   - 第三方拆解报告（iFixit/专业拆解媒体） = B+
   - 用户自制拆解视频（B站/YouTube 个人） = B-
   - 仅凭外观推测器件 = C

**检查点**：
- [ ] 每个进入"拆机"深度的竞品至少有结构拆解记录（不要求完整 BOM）
- [ ] 每个可识别的关键器件（主控、通信、传感器、电源）有型号/规格记录
- [ ] BOM 估算中每个器件标注价格来源和查询日期
- [ ] 无法识别的器件显式标记为"未识别"并说明原因（打磨/定制/封胶遮挡）
- [ ] BOM 成本总和的置信度已标记（≥80% 器件可识别 → 中置信度；<80% → 低置信度）

---

### Step 4: 供应链追溯

**输入**：Step 3 的器件识别结果 + 行业报告 + 供应商数据库

**操作**：
1. 对每个竞品的关键器件，追溯供应商来源：
   - 芯片：通过丝印/型号反推原厂（如 ESP32 → 乐鑫；nRF52840 → Nordic）
   - 传感器：通过型号反推供应商（如 BME280 → Bosch Sensortec）
   - 电池：通过电芯标识反推电芯厂
   - 结构件：通过模具编号/外观特征推断代工厂
2. 绘制竞品间共享供应商矩阵：识别哪些供应商同时向多个竞品供货
3. 识别供应链风险点：
   - 独家供应商（竞品 A/B/C 均使用同一厂商的某器件）
   - 单一来源器件（市场上仅 1-2 家供应商的专用芯片）
   - 地缘风险器件（某地区产能集中的器件）
4. 写入 evidence.csv 和 assumptions.csv：
   - 可确认的供应商关系 → evidence.csv（source_grade: 芯片原厂官网确认 = B；行业文章推断 = C）
   - 推断但未确认的供应商关系 → assumptions.csv（confidence: 中或低）

**检查点**：
- [ ] 至少识别 3 个关键器件品类的供应商分布（如 MCU 供应商、通信芯片供应商、传感器供应商）
- [ ] 共享供应商矩阵至少覆盖 2 个以上竞品
- [ ] 每个 supply chain risk 关联到 ≥1 条 evidence 或 assumption 记录

---

### Step 5: 跨竞品对比矩阵

**输入**：Step 2-4 的所有分竞品数据和 evidence 记录

**操作**：
1. 构建多维对比矩阵：

**功能/性能对标表**：

| 指标 | 竞品A | 竞品B | 竞品C | 我方目标 | 数据来源 |
|------|-------|-------|-------|---------|---------|
| 核心功能（列举） | | | | | |
| 关键性能参数 | | | | | |
| 通信协议 | | | | | |
| 认证覆盖 | | | | | |
| 功耗/续航 | | | | | |
| 安装耗时 | | | | | |

**成本结构对比表**：

| 成本项 | 竞品A | 竞品B | 竞品C | 置信度 |
|--------|-------|-------|-------|--------|
| BOM 成本 | | | | |
| 推测出厂价 | | | | |
| 零售价格带 | | | | |

**供应链对比表**（共享供应商矩阵）：

| 器件品类 | 竞品A供应商 | 竞品B供应商 | 竞品C供应商 | 供应商集中度 |
|---------|-----------|-----------|-----------|------------|
| MCU | | | | |
| 通信芯片 | | | | |
| 传感器 | | | | |

2. 标注对比中的关键发现（每个发现必须有 evidence_id 关联）

**检查点**：
- [ ] 对比矩阵中每个竞品的每个指标值有 evidence_id 关联（非空）
- [ ] 我方目标列已基于市场定位和成本目标初步设定

---

### Step 6: 差异化机会分析

**输入**：Step 5 的对比矩阵 + 用户评论分析（Step 2 的用户口碑维度）

**操作**：
1. **识别竞品 overserved 区域**：竞品提供了用户不关心的过度设计（如过多指示灯、不使用的功能模式、过剩的材质等级），这些是可削减成本的区域
2. **识别竞品 underserved 区域**：用户高频吐槽的功能缺失、性能不足、体验断点，这些是差异化切入点
3. **识别价格空白带**：竞品覆盖的价格带与用户愿意支付的价格带之间的 gap
4. **识别技术迁移机会**：从其他品类可借鉴的成熟方案或新进入消费级市场的技术
5. 将差异化机会按"用户价值 × 实现难度"矩阵归类：
   - 高价值 + 低难度 → 快速跟进
   - 高价值 + 高难度 → 核心差异化投资
   - 低价值 + 低难度 → 表内竞争
   - 低价值 + 高难度 → 不做

每组差异化机会的结论写入 report 第 11 章，关联到对应的 evidence_id。

**检查点**：
- [ ] 至少识别 3 个 underserved 机会（来自用户差评/投诉分析）
- [ ] 至少识别 2 个 overserved 机会（可削减成本的设计点）
- [ ] 每个机会标注"输入到哪里"（MRD / 产品定义 / PRD / 验证计划）

---

### Step 7: 生成竞品研究分析报告

**输入**：Step 1-6 的所有数据、evidence 记录、assumptions 记录

**操作**：
1. 按本 Skill 第 5 节"Output Structure"中完整的报告模板结构，逐章节填入分析内容
2. 撰写摘要（≤500字），严格按摘要格式规范：路由影响发现、产品定义约束发现、PM 需决策的开放问题、什么新证据会改变结论。每项 ≤2 句话
3. 填写"输入来源表"（章 0）——与 hw-market-study 的输入输出映射
4. 运行自检：
   - 报告中的每个数字/声明/对比值是否能在 evidence.csv 中找到对应记录？
   - 摘要是否 ≤500 字？
   - 输入来源表是否完整（无"缺失"状态未说明的条目）？
5. 写入 evidence.csv（流式写入，Step 2-4 过程中已完成；Step 7 仅做最终完整性检查）
6. 写入 assumptions.csv（所有标记为"未确认"或"推测"的判断）

**检查点**：
- [ ] 报告完整覆盖 0-12 所有章节（共 13 个章节，含摘要）
- [ ] 摘要 ≤500 字
- [ ] 输入来源表中每一行的"本报告处理方式"非空
- [ ] 报告中所有证据引述都有 evidence_id
- [ ] assumptions.csv 中每条记录的 validation_method 有明确验证路径
- [ ] 报告末尾有"什么新证据会改变结论"章节

---

## 5. Output Structure（输出结构）

### 输出文件

1. `output/{project}/competitive_analysis_report.md` — 完整竞品研究分析报告
2. `registers/evidence.csv` — 新增 evidence 记录（流式写入，每发现即写入）
3. `registers/assumptions.csv` — 新增 assumption 记录

### evidence.csv 写入格式

每条记录使用以下字段（必须精确匹配）：

```
evidence_id,title,source_type,source_name,url_or_path,date_collected,source_grade,direct_quote,importance,related_doc,related_section,summary,confidence,notes
```

| 字段 | 说明 | 竞品分析特定取值 |
|------|------|----------------|
| evidence_id | `EV-{project}-{seq}` | 例: EV-CWLS-015 |
| title | 发现标题（≤50字） | "竞品A 主控芯片为 ESP32-S3" |
| source_type | 来源类型 | `官方资料` / `电商页面` / `销售数据` / `用户评论` / `社媒内容` / `测评视频` / `购买记录` / `安装记录` / `拆机照片` / `BOM估算` / `售后记录` / `认证公告` |
| source_name | 来源名称 | 京东商品页 / B站 @博主名 / iFixit / LCSC |
| url_or_path | URL 或本地图片路径 | 竞品电商链接、拆机照片存储路径 |

### 硬件领域 source_grade 赋级规则

| 等级 | 源类型（硬件特定） | 可否支撑核心结论 |

| **B+** | 专业拆解报告（iFixit）、自有拆解（器件丝印可读）、芯片原厂技术文档 | 可以 |

## 6. Quality Bar（最低质量标准）

Reviewer 将按此 checklist 逐项检查。每条未通过的项目标记为 finding，severity 按标注执行。

- [ ] **QB-01: 摘要格式合规** — 摘要 ≤500 字，包含路由影响发现、产品定义约束发现、PM 需决策的开放问题、什么新证据会改变结论，共 4 个子节，每项 ≤2 句话。超限或缺失子节 → severity: blocker
- [ ] **QB-02: evidence 覆盖率** — 报告中对标矩阵（第 10 章）的每个数据格有关联的 evidence_id；第 3 章桌面数据的每条"结论"有关联 evidence_id。缺失关联的对比值 → severity: high
- [ ] **QB-03: source_grade 无空值** — evidence.csv 中所有本次写入记录的 `source_grade` 不为空。空值 → severity: blocker
- [ ] **QB-04: direct_quote 长度合规** — evidence.csv 中所有本次写入记录的 `direct_quote` 不为空且 ≥5 个字符。"参见 XX"或空字符串 → severity: high
- [ ] **QB-05: BOM 置信度显式声明** — 第 8 章 BOM 合计行和第 9 章成本推断表中，每条估算值标注置信度（高/中/低），且每条假设在 assumptions.csv 中有对应记录。缺失 → severity: blocker
- [ ] **QB-06: 输入来源表完整性** — 第 0 章"与产品市场研究和产品规划的关系"表格中，每行的"本报告处理方式"非空。空行 → severity: medium
- [ ] **QB-07: 拆机数据局限性声明** — 报告中凡使用拆机数据之处，显式声明样本量（拆解设备数量和版本/批次）。缺失声明 → severity: high
- [ ] **QB-08: "什么新证据会改变结论"章节非空** — 至少列出 2 项会改变核心结论的新证据类型。空章节 → severity: medium

## 7. Tool Integration（工具链）

### 主要工具

| 工具 | 用途 | 边界 |
|------|------|------|
| **WebSearch** | 电商表现搜索、用户评论聚合搜索、认证公告搜索、供应链信息搜索 | 中文查询优先百度源；英文查询优先 Google 源 |
| **WebFetch** | 获取竞品官网产品页、电商详情页、认证数据库页面的具体内容 | 不支持需登录的页面；不支持动态渲染页面（SPA） |
| **agent-reach** | 社媒讨论采集（小红书/B站/抖音/知乎/YouTube）、测评视频内容获取 | 仅采集公开内容；不做发帖/评论等写操作 |
| **lcsc** | 器件识别后的价格查询、规格确认、数据手册下载 | 仅覆盖 LCSC 在售型号；非通用元器件需切换至 digikey/mouser |
| **Read** | 读取上游文档（market study 报告）和已有台账 | — |
| **Write** | 写入竞品分析报告到 `output/{project}/` | 不覆盖已有报告（除非显式要求更新） |
| **Edit** | 向 evidence.csv 和 assumptions.csv 追加新行 | 仅追加，不修改已有行（仅 Reviewer 可修改台账） |

### 降级链

| 主工具 | 不可用时的备选 | 降级影响 |
|--------|--------------|---------|
| WebSearch（中文） | WebFetch 直接访问已知电商 URL | 覆盖面收窄；置信度降级为"中" |
| agent-reach（社媒） | WebSearch 搜社媒站内 | 丢失实时性和内容深度；source_grade 降为 D |
| lcsc（器件价格） | 1688/digikey/mouser 网页搜索 | 价格精度下降；BOM 置信度降为"低" |
| WebFetch 无法获取某电商页面 | 标记为"数据不可得" | 在报告对应维度标注"未覆盖" |

### 工具质量门禁

- WebSearch 搜索结果中，优先使用 `allowed_domains` 限定到电商平台和品牌官网域
- WebFetch 获取的电商页面内容，必须在 evidence.csv 中记录 `date_collected`（页面内容可能变化）
- lcsc 查询的价格需标注"批量价格"vs"零售价格"，以及查询数量级

## 8. Best Practices（最佳实践）

### 好的输出 vs 差的输出

**好的竞品对标（✓）**：

```markdown
| 指标 | 竞品 A（X 品牌 Y 型号） | 竞品 B（Z 品牌 W 型号） | 我方目标 | 证据 |
|-|-|-|-|-|
| 连接稳定性 | "2.4G Wi-Fi 下偶发断连" — 京东用户评论（n=47条相关差评/总数3,200条）[EV-CWLS-023] | "未发现断连投诉" — 天猫评价第一页无连接相关差评 [EV-CWLS-024] | 零断连投诉 | EV-CWLS-023, EV-CWLS-024 |
```

**差的竞品对标（✗）**：

```markdown
| 指标 | 竞品 A | 竞品 B | 我方目标 |
|-|-|-|-|
| 连接稳定性 | 一般 | 好 | 优秀 |
```

差的输出的问题：无数据来源、无量化依据、无证据编号、"一般/好/优秀"不可验证。

**好的 BOM 估算（✓）**：

```markdown
| 模块 | 器件 | 型号/规格 | 数量 | 估算单价(¥) | 估算小计(¥) | 备注 |
|-|-|-|-|-|-|
| 主控 | MCU | ESP32-S3 (丝印确认) | 1 | 12.5 | 12.5 | LCSC批量价 C2928453, 2026-07-29查询, 1k+价格 |
| 电源 | DC-DC | SY8088 (丝印确认) | 1 | 0.8 | 0.8 | LCSC批量价 C123456, 1k+价格 |
| 传感器 | 温湿度 | 未识别（QFN封装，无丝印） | 1 | 2.0-5.0 | 2.0-5.0 | 区间估计，同类芯片价格范围 |
```

**差的 BOM 估算（✗）**：

```markdown
| 模块 | 器件 | 价格 |
|-|-|-|
| 主控 | ESP32 | 10 |
| 传感器 | 温湿度传感器 | 3 |
```

差的输出的问题：无具体型号和丝印确认、无价格来源和查询日期、未识别器件未标注而直接填入数值、无置信度标记。

### 常见陷阱

1. **把竞品"宣传的"当"真实的"**：品牌详情页声称的"IP65防水"不等同于实际达到 IP65。应在对标中标明"品牌自述，未独立验证"。
2. **忽略竞品的区域差异**：同一型号在国内外市场可能使用不同芯片方案（如国内版用 ESP32，海外版用 nRF5340 以满足 FCC 认证）。仅拆解一个版本不足以代表全系列。
3. **忽视竞品代际迭代**：竞品可能在调研期间发布了新型号。报告中应标注"本次研究基于 X 年 X 月市场上可获取的版本"，并记录已知的代际变化。
4. **BOM 成本忽略规模效应**：竞品若出货量达百万级，其器件采购价可能是 LCSC 公开批量价的 50-60%。BOM 估算应标注"按公开批量价估算，竞品实际采购价可能低 20-50%"。
5. **用户评论的幸存者偏差**：电商评论区经过平台筛选和商家干预（删差评、刷好评）。高频差评主题比差评率更有参考价值；好评数绝对值不等于用户满意度。
