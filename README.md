# 智能硬件 PM Agent

> 将产品经理文档模版包的方法论，实现为可独立运行的 3-Agent 协作系统（Researcher / PM / Reviewer）。

**📖 完整使用说明：[使用说明.md](使用说明.md)**

## 快速开始

1. 确保已安装 Claude Code，`AGENTS.md` 会在会话启动时自动加载
2. 新项目：对 Claude Code 说 **"帮我启动一个新项目"** → `hw-intake` 触发引导式访谈 → 路由判定 → Gate 1 审批
3. 研究阶段：各 Researcher Skill 串行执行，产出研究报告 + evidence.csv
4. 规划阶段：PM Skills 基于批准的研究报告产出产品文档
5. 每个 Gate 前运行 `python3 validators/scripts/validate_registers.py` 确保台账完整性

# 智能硬件产品经理文档模板包

## 使用方式

本模板包用于智能硬件公司的产品规划、产品定义、需求管理和验证管理。推荐按项目风险和创新程度裁剪使用，而不是所有项目都机械套完整流程。

## 完整流程

```text
00 项目启动卡
-> 00A 文档关系与追踪说明
-> 01 产品市场与机会研究报告
-> 09 竞品研究分析报告（按项目需要作为专项研究输入）
-> 10 用户研究与VOC分析报告（按项目需要作为专项研究输入）
-> 14 产品规划报告（整合市场/竞品/用户研究，形成正式三定）
-> 02 MRD 市场需求文档
-> 03 BRD 商业需求文档
-> 04 产品定义文档
-> 05 PRD 产品需求文档
-> 06 验证计划
-> 11 项目复盘与方法沉淀记录（阶段评审或项目结束后使用）
-> 12 L1 轻量产品定义/PRD 合并文档（轻量流程使用）
-> 13 项目任务包与交付检查表（启动卡确定流程后使用）
-> registers 证据/假设/风险/决策/需求/追踪登记表
```

## 三档流程裁剪

| 流程级别 | 适用项目 | 必需文档 | 可裁剪文档 |
|-|-|-|-|
| L1 轻量流程 | 缺陷修复、小功能迭代、体验优化、替代料、法规/认证强制改动 | 项目启动卡、L1 轻量产品定义/PRD 合并文档、验证计划或验证清单、风险记录 | 完整研究报告、MRD、BRD、独立产品定义 |
| L2 标准流程 | 重要功能、新型号、客户定制、现有品类升级 | 项目启动卡、MRD/BRD 合并版、必要竞品研究、必要用户/VOC研究、产品定义、PRD、验证计划 | 完整行业研究、独立 MRD、独立 BRD |
| L3 完整流程 | 全新品类、新市场、新平台、高投入项目 | 全部文档，通常包含市场与机会研究、竞品专项研究、用户/VOC专项研究和产品规划报告 | 不建议跳过关键阶段 |

流程裁剪只能裁剪文档形式，不能裁剪关键判断。标准流程和轻量流程的必需文档开头都要说明输入来源、替代证据和缺口处理方式。

## 不应跳过的最小内容

无论流程多轻，至少保留：

- 目标用户和使用场景
- 产品范围和不做清单
- 关键假设和证据来源
- 风险和验证计划
- 验收标准

## 方法组合

- 华为五看三定：五看用于产品市场与机会研究，三定用于产品规划报告的综合决策。
- 麦肯锡方法：用于问题树、MECE、假设驱动、证据链和结论表达；每个五看章节都要回答问题、假设、证据、分析过程、阶段结论和不确定性。
- 波特方法：用于看行业和看竞争，重点分析五力、价值链、利润池、竞争优势、替代品和进入壁垒。
- 看行业五个子模块：政策与监管研究、技术趋势研究、产业链/价值链研究、市场结构与规模分析、行业格局与核心玩家。
- 产品经理方法：用于 JTBD、用户旅程、用户故事地图、MVP 和路线图。
- 智能硬件竞品研究：用于桌面数据、购买安装体验、拆机、BOM、成本和体验对标，并输入产品规划报告。

## 方法闭环

本模板包不只用于写文档，还用于建立产品判断的证据链和复盘机制。

- 用 `00A_文档关系与追踪说明.md` 理解文档流转、输入输出、主数据归属和追踪规则。
- 用 `13_项目任务包与交付检查表.md` 在启动卡确定流程后建立任务包，跟踪必需文档、输入补齐、评审决策和风险验证。
- 用 `registers/evidence.csv` 记录证据，避免结论无来源。
- 用 `registers/assumptions.csv` 记录尚未验证但影响决策的假设。
- 用 `registers/risks.csv` 记录市场、技术、供应链、认证、售后和商业风险。
- 用 `registers/decisions.csv` 记录立项、范围、定位、流程裁剪和关键技术选择。
- 用 `registers/traceability.csv` 追踪证据、研究发现、产品定义、PRD 和验证项之间的关系。
- 用 `registers/method_learnings.csv` 记录可复用的方法修正、模板字段、裁剪规则和检查项。
- 用 `11_项目复盘与方法沉淀记录.md` 把验证偏差、上市反馈和售后经验转成团队方法沉淀。
