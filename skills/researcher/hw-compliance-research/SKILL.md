# hw-compliance-research — 产品合规研究

## 1. Purpose（目的）

本 Skill 是 Researcher Agent 在合规研究中的核心技能。它解决一个关键问题：**产品要在目标市场合法上市，必须满足哪些强制合规要求、适用哪些标准、需要走什么认证路径。** 在 Agent 工作流中，hw-compliance-research 位于研究阶段的中后段 —— 它接收产品画像（product_profile）中的 32 合规模块激活判定，对每个激活模块进行标准检索和合规定级，产出合规档案和认证路径图。其结论直接影响产品定义（hw-product-definition）的合规约束章节和验证计划（hw-validation-plan）的检测项。

## 2. Context（上下文/适用场景）

### 触发条件
- Gate 1 已批准，路由判定为 L2（产品衍生）或 L3（新品类）
- product_profile 已生成，包含产品品类、目标市场、供电方式、通信方式、物理属性等关键事实
- L1（降本/衍生）路由不触发本 Skill —— L1 产品的合规要求在原有产品上已满足，仅在 hw-market-study 的 Step 4 中做简要政策扫描

### 前置条件
- `project_profile.json` 或 product_profile 文档已生成，32 合规模块激活状态已完成初步判定
- Gate 1 审批记录可读，路由等级已确认
- `registers/evidence.csv` 已初始化（至少包含 CSV header 行）
- `registers/assumptions.csv` 已初始化
- hw-market-study 的 Step 4（政策与监管研究）产出可供参考复用

### 输出消费方
- **hw-product-definition**：读取合规约束（must/should/comply 标准清单），写入产品定义中的合规要求章节
- **hw-validation-plan**：读取 must 级标准的验证方式和试验项，作为检测计划的输入
- **hw-product-strategy**：读取认证路径时间线，评估对上市时间的影响
- **人工 PM**：在 Gate 审批中判断合规风险是否可接受，确认认证预算
- **测试团队**（通过 hw-validation-plan 间接消费）：Phase 3a 试验项确定 → Phase 3b 试验工程

## 3. Operating Principles（操作原则）

### 原则 1：模块全覆盖不遗漏（Full Module Coverage）
32 合规模块的激活判定是合规研究的唯一起点。每一个 activated 模块必须有至少 1 条标准匹配记录；如果某模块确实无标准匹配，必须显式写 gap 声明并说明替代方案。

- **反面行为**：对 M01（电器安全）模块因为"显而易见"而不写标准，或对 A09（电信设备进网许可）模块因为"产品好像有 Wi-Fi"而跳过确认。
- **违反后果**：漏掉的合规模块可能在 Gate 6/7 才暴露，导致产品定义需要大幅修改或上市延期。

### 原则 2：标准状态必须验证（Standard Status Verification）
每条标准必须标注当前状态（现行有效 / 已废止 / 即将实施 / 征求意见稿），不能只写"GB xxxx-2016"而不检查是否已被新标准替代。废止标准引用 → Reviewer blocker。

- **反面行为**：引用 GB 4943.1-2011 而不检查它已被 GB 4943-2022 替代。
- **违反后果**：产品按旧标准设计或检测，导致认证不通过，需要重做型式试验。

### 原则 3：must 级标准链接必须可达（Must-Grade Link Accessibility）
每条定级为 must（强制）的标准，其获取 URL 必须经过验证可达。不能使用死链、失效链接或需特殊权限的门户页面作为唯一来源。

- **反面行为**：所有 must 级标准统一写 `https://openstd.samr.gov.cn/` 而不验证具体页面是否可打开。
- **违反后果**：PM 无法获取标准全文，合规判断建立在"听说过这个标准"而非"读过这个标准"上。

### 原则 4：不确定即申报（Uncertainty Must Be Declared）
模块激活状态为 uncertain 时，必须将其列入报告的"风险与不确定性"章节，标注建议确认方（如"建议研发确认是否有加热元件"）。不能默默标记为 excluded。

- **反面行为**：M06（发热/热安全）不确定是否触发，直接标 excluded 且不通知任何人。
- **违反后果**：产品设计完成后被检测机构告知需满足热安全标准，PCB 布局和散热设计需返工。

### 原则 5：流式写入证据（Streaming Write）
发现标准条目后，**立即**将标准信息写入 `registers/evidence.csv`，不等报告写完再批量回填。每条标准对应一条 evidence 记录。

- **反面行为**：先收集 50 条标准链接，报告写完后一次性补 evidence.csv，导致标准编号、名称、状态与源页面不一致。
- **违反后果**：报告与 CSV 不一致，触发 6 号质量规则（CSV 是权威），校验脚本报 blocker。

### 原则 6：认证路径必须有时间线（Certification Path Timeline）
认证路径不能只写"需要 CCC 认证"，必须给出每一步的典型周期和里程碑。时间线是 PM 评估上市可行性的核心依据。

- **反面行为**：认证路径写成"CCC 认证 → 型式试验 → 工厂检查 → 获证"而不给任何时间估算。
- **违反后果**：PM 误判上市时间，项目计划缺乏可信度。

### Step 1：加载项目上下文与产品画像

- **输入**：读取 product_profile 文档（含 product_profile.json 或 project_profile.json）、Gate 1 审批记录、hw-market-study 报告中"4.1.1 政策与监管研究"章节
- **操作**：
  1. 提取产品名称、产品品类、目标市场列表（中国市场 + 出口市场）
  2. 提取产品关键属性：供电方式（电池/市电/两者）、通信方式（无/Wi-Fi/BLE/Zigbee/蜂窝）、是否含电机/加热/激光/电池/传感器、目标用户（儿童/成人/通用）
  3. 提取项目路由等级（L2/L3），决定合规研究深度：L2 → 至少覆盖 discover + comply；L3 → 覆盖 discover + comply + test（Phase 0-2 + Phase 3a）

- **检查点**：
  - 产品品类、目标市场、供电方式、通信方式 4 项全部提取
  - L2/L3 路由已确认，合规研究深度已确定
  - hw-market-study 中已有的认证线索已纳入待复用清单

### Step 3：制定检索策略（Analyst 角色）

- **输入**：Step 2 的激活模块清单
- **操作**：
  1. 对每个 activated 模块，确定检索关键词（模块关键词 + 产品品类关键词）
  2. 确定检索方向：
     - **P0 — GB 强制性国标 + GB/T 推荐性国标**：目标库 `https://std.samr.gov.cn/` + `https://openstd.samr.gov.cn/` 交叉验证
     - **P1 — 行业标准（行标/团标）**：行业部门网站（工信部/住建部/应急管理部/卫健委等）+ `https://www.ttbz.org.cn/`
     - **P2 — 地方标准 + 国际采标**：地方标准信息平台 + ISO/IEC/EN 等国际标准组织
     - **P3 — 企业标准 + 实施规则**：认证机构网站（CQC/CCIC 等）的 CCC 实施规则
  3. 对每个模块标注建议的检索优先级和预期标准类型
  4. 生成 keywords_matrix：模块 ID → 检索词列表 → 优先级（P0/P1/P2/P3）→ 预期数据库
- **检查点**：
  - 每个 activated 模块至少有 1 组检索关键词
  - P0 检索方向优先覆盖所有 activated 模块的强制标准
  - 对 CCC 相关模块（A01），必须检索对应的 CCC 实施规则（CNCA-Cxx-01:202x）

---

### Step 4：并行标准检索（GB_Retriever / TB_Retriever / SUPP_Retriever）

- **输入**：Step 3 的 keywords_matrix
- **操作**：
  1. **GB_Retriever**：检索 P0 方向 —— 强制性国标（GB）和推荐性国标（GB/T）
     - 搜索 `https://openstd.samr.gov.cn/` 的标准公开系统
     - 搜索 `https://std.samr.gov.cn/` 的标准信息查询
     - 对 CCC 目录产品，检索对应 CNCA 实施规则
     - 对每个检索结果，记录标准编号、名称、状态（现行/废止/即将实施）、获取层级
  2. **TB_Retriever**：检索 P1 方向 —— 行业标准 + 团体标准
     - 搜索对应行业部门网站（如工信部→通信行业标准 YD、住建部→建筑工业行业标准 JG）
     - 搜索 `https://www.ttbz.org.cn/` 的团体标准信息平台
     - 对每个结果，记录归口单位、标准类型
  3. **SUPP_Retriever**：检索 P2/P3 方向 —— 地方标准 + 国际标准 + 企业标准
     - 搜索地方标准信息平台
     - 搜索 ISO/IEC/EN/IEEE 等国际标准组织（如适用）
     - 搜索 CQC/CCIC/中检南方等认证机构网站的认证规则和实施细则
  4. **三个 Retriever 并行运行**，各自独立写入 evidence.csv，格式如下：
     - `evidence_id`: `EV-{project}-{seq}`
     - `title`: 标准编号 + 标准名称（如"GB 4706.1-2005 家用和类似用途电器的安全 第1部分：通用要求"）
     - `source_type`: 政策文件
     - `source_name`: 标准发布机构（如"国家标准化管理委员会"）
     - `url_or_path`: 标准的获取 URL（按获取层级标注可访问性）
     - `source_grade`: 政府/标准文件 → A
     - `direct_quote`: 标准的适用范围或关键条款原文
     - `importance`: central（强制标准）/ supporting（推荐标准）/ tangential（参考标准）
     - `related_doc`: "17_产品合规研究报告"
     - `related_section`: 2（标准地图）
     - `summary`: 1-2 句话概括此标准对产品的合规意义
     - `confidence`: 高（已验证现行有效）/ 中（未完全验证状态）/ 低（仅间接引用）
     - `notes`: 获取层级 + 状态验证方式
- **检查点**：
  - 每个 activated 模块至少有 1 条 evidence 记录，或已写入 gap 声明
  - 每条 GB 强制性国标的获取 URL 已验证可达
  - P0 检索覆盖所有 A 类激活模块和 B 类中与安全相关的激活模块
  - 每个 Retriever 的检索结果按模块 ID 整理，避免重复提交

**检索优先级与数据库表**：

| 优先级 | 标准类型 | 数据库/来源 | 检索工具 |
|--------|---------|------------|---------|
| P0 | GB 强制性国标 + CCC 实施规则 | openstd.samr.gov.cn, std.samr.gov.cn, CNCA 网站 | WebSearch + WebFetch |
| P1 | GB/T 推荐性国标 + 行业标准 (YY/QB/JG/YD 等) | 行业部门网站, ttbz.org.cn | WebSearch + WebFetch |
| P2 | 团体标准 + 地方标准 | ttbz.org.cn, 省级标准平台 | WebSearch |
| P3 | 国际采标 (ISO/IEC/EN) + 企业标准 | iso.org, iec.org, 认证机构网站 | WebSearch + WebFetch |

### Step 5：验证与去重（Validator 角色）

- **输入**：Step 4 三个 Retriever 产出的所有 evidence 记录
- **操作**：
  1. **去重**：同一模块下，同一标准编号的不同检索结果合并。保留所有源的 URL、获取层级，不丢弃任何数据
  2. **标准状态验证**：对每条标准，确认状态（现行有效 / 已废止 / 即将实施 / 征求意见稿）
     - 搜索"标准编号 + 废止"、"标准编号 + 替代"等关键词
     - 在 openstd.samr.gov.cn 上查证该标准的状态标记
     - 废止标准：标注"已废止，替代标准：XXX"，不列入 standards_map 的 active 标准
  3. **模块覆盖率计算**：
     - `activated 模块数` → `N_activated`
     - `已匹配标准模块数` → `N_matched`
     - `覆盖率 = N_matched / N_activated * 100%`
     - 对于 `N_matched < N_activated` 的 gap 模块，写入 gap 声明并说明替代方案
  4. **URL 可达性验证**：对每个 must 级标准的 URL 执行可访问性检查（用 WebFetch 确认页面可以加载）
  5. 生成 validated_standards 清单，写入报告第 2 节"标准地图"
- **检查点**：
  - 覆盖率 ≥ 80% 视为通过（Gate 前置条件）
  - 覆盖率 < 80%：gap 模块显式声明，列入"风险与不确定性"
  - 无废止标准出现在 active 标准清单中
  - 所有 must 级标准的 URL 已验证可达

### Step 6：合规定级（Phase 2 合规映射）

- **输入**：Step 5 的 validated_standards 清单
- **操作**：
  1. 对每条标准进行合规定级（must / should / comply），填入报告第 3 节"合规档案"
  2. **定级规则**：
     - **must**（强制）：属于强制性国标（GB，不含 GB/T）、CCC 实施规则、电信设备进网许可规则、医疗器械注册要求、法律法规引用的标准。不满足 → 无法上市
     - **should**（推荐）：GB/T 推荐性国标中与用户安全/产品互操作性/能效直接相关的条款、行业标准中的功能规范、国际采标。不满足 → 影响竞争力或渠道准入
     - **comply**（参考）：团体标准、地方标准、国际标准中声明即符合的条款、暂无强制要求的参考标准。不满足 → 无直接影响，但可提升可信度
  3. 对每条 must 级标准，提取核心合规指标和限值：
     - 安全指标（如耐压、绝缘电阻、泄漏电流 → GB 4706.1 第 13/16 章）
     - EMC 指标（如辐射骚扰限值、传导骚扰限值 → GB/T 9254.1）
     - 无线指标（如发射功率、频率范围 → SRRC 相关标准）
     - 电池指标（如过充、短路、跌落 → GB 31241）
  4. 标注每条标准的验证方式（型式试验 / 自我声明 / 第三方检测 / 工厂检查）
- **检查点**：
  - 每条 activated 模块对应的标准都有定级
  - must 级标准至少列出 1 项核心指标 + 限值
  - 验证方式与标准要求的符合性评定方式一致

---

### Step 7：绘制认证路径图

- **输入**：Step 6 的 must 级标准清单 + 认证制度要求
- **操作**：
  1. 对每种认证类型，绘制完整流程图和时间线：

  **CCC 认证路径（必须详细绘制）**：
  ```
  阶段1: 型式试验 (4-8周)
    ├─ 送样准备 (样品准备 + 资料准备: 1-2周)
    ├─ 实验室检测 (2-4周)
    └─ 不合格整改 (如需: +2-4周)
      ↓
  阶段2: 工厂检查 (1-2天 + 报告审核 2-4周)
    ├─ 初次工厂审查
    └─ 不符合项整改 (如需: +2-4周)
      ↓
  阶段3: 获证发证 (1-2周)
    ├─ 型式试验报告审核
    ├─ 工厂检查报告审核
    └─ 颁发 CCC 证书
      ↓
  阶段4: 获证后监督 (每年/每18个月)
    ├─ 年度监督审核
    └─ 市场抽检
  ```

  2. 对其他认证类型（SRRC、电信设备进网许可、能效备案等），绘制各自的流程和时间线
  3. 给出关键路径的总时间估算（从最晚开始的认证到最早可以上市）
  4. 标注可以并行的认证步骤（如 CCC 型式试验和 SRRC 测试可并行进行）
  5. 给出费用估算（认证检测费、工厂检查费、证书费、年费）—— 标注为估算

  6. 将认证路径填入报告"3.2 认证路径"表
- **检查点**：
  - CCC 认证路径的 4 个阶段全部有时间估算
  - 并行/串行关系已标注
  - 费用估算有来源（认证机构网站公示价格 / 行业经验 / 标注"需询价"）
  - 关键路径总时间以月为单位给出

### Step 8：生成合规研究报告

- **输入**：Step 2-7 的所有产物
- **操作**：
  1. 按第 5 节"Output Structure"中的完整报告模板组织内容
  2. 先写各章节正文（1-5 节），再写摘要
  3. **摘要**：从各章节中提取 4 类信息（强制合规项 / 推荐合规项 / 认证关键里程碑 / 可改变结论的条件），每项 ≤2 句话。总字数 ≤500 字（中文字数统计）
  4. 填写**产品合规画像**（1.1 节）：产品名称、品类、目标市场、供电方式、通信方式
  5. 填写**32 合规模块激活判定表**（1.2 节）：32 行完整，不得有空行
  6. 填写**标准地图**（第 2 节）：已去重和验证的标准清单 + 模块覆盖率 + gap 声明
  7. 填写**合规档案**（第 3 节）：合规定级表 + 认证路径表
  8. 填写**输入来源与完整性**（第 4 节）：列出报告引用的所有输入及其完整性状态
  9. 填写**风险与不确定性**（第 5 节）：模块 uncertain + gap + 标准状态不确定等
- **检查点**：
  - 摘要 ≤500 字
  - 32 模块表完整（32 行全部填充）
  - 标准地图表与 evidence.csv 一致
  - 无占位符（"TBD"/"TODO"/"待补充"）

### Step 9：最终校验与完成

- **输入**：完成后的报告 + evidence.csv + assumptions.csv
- **操作**：
  1. 检查 evidence.csv 中本次写入的所有记录：14 个字段是否全部填充
  2. 检查每个 activated 模块是否有 ≥1 条 evidence 记录或已写入 gap 声明
  3. 检查 must 级标准的 URL 是否全部验证可达
  4. 执行字数统计确认摘要 ≤500 字
  5. 检查报告和 CSV 的一致性：报告中的标准编号、名称、URL 与 evidence.csv 一致
  6. 确认无占位符
  7. 确认 32 模块表的每条 uncertain 记录对应的假设已写入 assumptions.csv
- **检查点**：
  - 14 字段完整性通过
  - 模块覆盖率通过（≥80% 或所有 gap 已声明）
  - URL 可达性通过
  - 摘要字数通过
  - 报告-CSV 一致性通过

## 8. Best Practices（最佳实践）

### 好 vs 差的输出对比

#### 标准检索

| 模块覆盖 | 32 模块全部有判定，M06 heating 标 excluded 且写明"产品不含加热元件，无发热安全风险" | M06 heating 留空 |

#### 合规定级

| 维度 | 好的输出 | 差的输出 |
|------|---------|---------|
| must 定级 | GB 4706.1-2005 → must，依据：属 CCC 目录产品必须满足的强制性国标，不满足无法通过 CCC 型式试验 | 所有标准标 must |
| 核心指标 | "耐压测试：基本绝缘 1250V/1min，加强绝缘 3000V/1min（GB 4706.1 第 13.3 条）" | "需要满足安全要求" |
| 验证方式 | "型式试验（CCC 指定实验室检测）+ 工厂检查（CQC 年度监督）" | "第三方检测" |

### 常见陷阱

1. **仅查标准不查实施规则**：CCC 认证不仅需要满足 GB 标准，还需要满足 CCC 实施规则（CNCA 文件）。实施规则中可能包含标准未覆盖的特殊要求（如一致性检查、工厂质量保证能力要求）。
2. **忽略标准年号变更**：GB/T 9254.1-2021（替代 GB/T 9254-2008）、GB 4943-2022（替代 GB 4943.1-2011）等近年的重大标准替代。引用过时标准会导致产品按旧标准设计，检测不通过。
3. **SRRC 与电信设备进网许可混淆**：SRRC（无线电型号核准）管无线发射，电信设备进网许可（NAL）管蜂窝通信设备接入公众电信网。含蜂窝模块的产品两个都需要，不含蜂窝仅 Wi-Fi/BLE 的产品仅需 SRRC。
4. **RoHS 不只是一种标准**：中国 RoHS（GB/T 26572）与欧盟 RoHS（2011/65/EU）的限值和适用范围不同。产品如果同时在中国和欧盟销售，需分别满足。
5. **能效标识的触发条件被忽略**：许多产品品类（如适配器、显示器、灯具）在能效标识目录内，即使产品本身没有"节能"卖点也需要备案。
6. **C 类标识模块被遗漏**：有些团队认为标识是"包装设计的细节，最后补就行"，但 C01（产品标识标注）的强制要求（制造商名称、型号、额定值、生产日期等）如果没有在产品本体和包装设计中预留位置，后期很难补救。
7. **认证周期按理论最短值估算**：CCC 认证从送样到获证，理论上 30 个工作日可以完成，但实际通常需要 3-6 个月（含整改、排队、报告审核）。SRRC 类似，理论 60 个工作日，实际 2-4 个月。
8. **电池安全模块（M04）对所有含电池产品都激活**：即使是最小的纽扣电池，也需要满足 GB 31241（便携式电子产品用锂离子电池和电池组安全要求）和 GB 4943.1 附录 M 的电池相关条款。
